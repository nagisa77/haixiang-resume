# 海翔的简历工作台

这里保存你的原始简历、采访回答、可用于简历的事实、岗位信息以及每次简历版本。日后继续在这个工程对话即可；换一个对话也能从档案接着聊。

## 你可以直接这样说

- “今天聊十分钟，继续上次的项目。”
- “这件事我当时是这样做的……”
- “这个说法不准确，实际上是……”
- “这是一个 BOSS 岗位截图，帮我看看适合不适合，并做对应简历。”
- “对比两个版本，告诉我为什么改。”

不需要先把经历整理成漂亮的文字。先讲真实发生的事，系统负责追问、整理和改写。每轮只聊少量问题，没有数字也可以先讲过程。

## 信息如何保存

| 内容 | 位置 | 用途 |
| --- | --- | --- |
| 原始材料 | `sources/` | 保留初始 PDF 与来源索引 |
| 采访原话 | `interviews/` | 保留每轮回答，避免只剩润色后的描述 |
| 经历事实 | `profile/facts.json` | 区分已确认、旧简历导入、待确认提议及被更正的事实 |
| 下次从哪里聊 | `profile/state.json` | 保存已问问题、未解决问题与偏好 |
| 岗位资料 | `jobs/` | 每个岗位独立保存截图、要求与匹配分析 |
| 正在编辑 | `drafts/` | 内容与版式迭代 |
| 已归档版本 | `versions/` | 成品、修改说明、事实快照与文件校验值 |
| 制作技能 | `skills/haixiang-resume/` | 采访、定制、排版与归档规则 |

“已确认”表示你本人已明确陈述或确认，不表示已由第三方认证。旧简历信息可以进入明确标记的草稿；关键事实核实后，再生成可投递版本。改写会增强信息结构，不会补造业绩、项目规模或管理权限。

## 版本怎样追溯

版本使用 `v0001-20261010-baseline` 一类唯一编号。每版保留目标岗位、修改原因、每条经历对应的事实编号、事实来源，以及当时完整的档案快照。后来更正履历不会改写旧版本。

当前第一版是**通用母版草稿**：用于看结构与视觉，不代表旧简历内容已经逐条核实，也不是特定岗位的投递版。后续收到售前或项目交付岗位，会分别选择相关经历、调整重点并生成独立版本。

## 保存与同步

本项目同步到公开 GitHub 仓库：[nagisa77/haixiang-resume](https://github.com/nagisa77/haixiang-resume)。仓库包含制作脚本、原始简历、联系方式、采访记录、事实档案及已归档简历版本，内容可被公开查看；没有上传到招聘平台。

跨设备使用时克隆整个仓库，以保留采访与追溯关系；仅复制 PDF 无法保留这些资料。临时 PDF 检查图片、Python 缓存和本地凭据文件不纳入 Git 跟踪。
